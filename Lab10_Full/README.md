# Lab 10 — Integrated Authentication & Notifications

Run `flutter pub get` and `flutter run` on Android with internet access. Splash restores the DummyJSON session if a token exists. Log in with `emilys` / `emilyspass` (DummyJSON demo), restart to verify auto-login, then logout to clear the saved session. A local notification is requested after successful REST or Google login; on Android 13+ grant notification permission. Verify the notification in the device's system shade.

Google login is an alternative path. It needs your own Firebase project: enable Google sign-in in Firebase Authentication, register Android package ID from `android/app/build.gradle.kts`, add debug/release SHA-1 and SHA-256, run `flutterfire configure`, then import the generated `firebase_options.dart` in `lib/services/google_auth.dart` and replace `Firebase.initializeApp()` with `Firebase.initializeApp(options: DefaultFirebaseOptions.currentPlatform)`. Ensure required platform OAuth/web client configuration is present. Without configuration, the Google button is disabled with guidance. No Firebase credentials are included.

Dependencies: `http`, `shared_preferences`, `firebase_core`, `firebase_auth`, `google_sign_in`, `flutter_local_notifications`. Android manifest requests Internet and notification permission, and Gradle enables desugaring. Run `flutter analyze` and `flutter test` (tests use fake HTTP and mocked preferences). Google sign-in and delivery of notifications must be checked manually on a configured device. SharedPreferences/token-presence auto-login is a teaching exercise, not production-grade credential storage or token verification.
